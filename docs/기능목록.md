# 엮음AI(YeokkeumAI) AI 플랫폼 — 공공 RFP 수용 기능목록 v0.1

> 목표 = **일반적으로 쓰기 편한 범용 AI 플랫폼**이면서, **공공기관 발주 RFP가 요구하는 기능·통과조건을 최대한 수용**.
> 근거 = 조달청·NIA 실 수요 리서치(2026-08) + 표준 SW사업 요구사항 상세화 가이드(기능/성능/…/지원 분류) + 법제도(전자정부법·장애인차별금지법·개인정보보호법·CSAP·N2SF).
> ⚠️ 정직: **단일 플랫폼이 "모든 RFP"를 문자 그대로 충족할 수는 없다.** 이 목록은 (a)공공 AI 수요의 상위집합 + (b)거의 모든 정보화 RFP의 공통분모(비기능·법제도 통과조건)를 커버해, **개별 RFP엔 설정/모듈 조합으로 대응**하는 것을 목표로 한다.

## 0. 포지셔닝 (한 줄)

**"온프렘/내부망(N2SF)에서 도는, 국산 K-AI도 물리는 벤더무관 게이트웨이 위에, 규정검토 RAG·문서작성/요약·민원 상담·업무 에이전트를 얹고, 모든 처리에 사람 승인(HITL)과 감사로그를 붙인, 웹접근성·보안인증까지 갖춘 공무원 업무보조 AI 플랫폼."** — 자율성이 아니라 **통제·책임성·연계**를 파는 물건.

## A. AI 핵심 기능 (조달청·NIA가 실제로 원하는 것)

### A1. LLM 게이트웨이 (모델 벤더무관) ★NIA 신규 핵심요구
- A1-1 다중 프로바이더 추상화: OpenAI호환/Gemini/**국산 K-AI(하이퍼클로바X·EXAONE·A.X·솔라 등) 최소 1종 의무** 핫스왑
- A1-2 온프렘/사설 엔드포인트 연결(내부망 배포 모델·게이트웨이 URL 지정)
- A1-3 모델 라우팅(용도·비용·보안등급별), 폴백, 레이트리밋, **토큰·비용 집계/쿼터**
- A1-4 프롬프트/응답 로깅·마스킹(개인정보 비식별), 캐시
- A1-5 임베딩/재랭커 프로바이더 추상화(RAG용)

### A2. RAG — 규정/지식 검색·검토 ★조달청·NIA 최우선
- A2-1 문서 수집·파싱(HWP/HWPX·PDF·DOCX·XLSX·이미지 OCR·표), 청킹, 임베딩, 벡터스토어
- A2-2 하이브리드 검색(BM25+벡터)+재랭킹, 출처 인용(문단·페이지), 근거 하이라이트
- A2-3 **규정기반 검토 에이전트**: 작성물을 법률·시행령·행정규칙·조례·내규에 비춰 위반/리스크 지적 + 수정문안 제안
- A2-4 지식베이스 버전관리·권한별 접근·기관별 격리(멀티 KB)
- A2-5 최신성: 소스 갱신 감지·재색인, 만료/오래된 근거 경고

### A3. 문서 생성·요약·변환 ★공통 상용요구
- A3-1 초안 작성(보고서·공문·RFP·산출내역서·회의록 템플릿), 문체/서식 프리셋
- A3-2 요약(장문·회의·다문서 통합), 핵심추출, 표/불릿 변환
- A3-3 번역(다국어, 외국인 민원), 맞춤법·행정용어 교정
- A3-4 **HWP/HWPX 입출력**(공공 필수 포맷), 서식 보존
- A3-5 문서 비교/변경점(diff), 결재 문안 정합성 점검

### A4. 대화형 상담·민원 챗봇
- A4-1 지식근거 기반 Q&A(RAG 그라운딩, 환각 억제·근거 표기)
- A4-2 다국어 상담, 음성 입출력(STT/TTS) 옵션
- A4-3 민원 자동분류·라우팅·초안응답, 상담 이력·만족도
- A4-4 상담 불가/불확실 시 **정직 거절 + 담당자 이관**(할루시네이션 방지)

### A5. 업무 에이전트 + 도구 연계 (MCP) ★NIA 이동방향
- A5-1 **MCP(Model Context Protocol) 도구 서버 연동**(내부 시스템·DB·API·파일)
- A5-2 도구 레지스트리·**allowlist**·기관별/역할별 도구 스코프
- A5-3 다단계 작업 오케스트레이션(계획→도구호출→검증), 예약/트리거
- A5-4 **HITL 승인 게이트**: 변경/전송/실행형 도구는 사람 승인 후 실행(읽기는 무승인)
- A5-5 실행 결과·근거·비용의 감사 추적

### A6. 데이터 분석·이상탐지
- A6-1 정형/비정형 데이터 질의(자연어→SQL/집계), 시각화
- A6-2 이상탐지(패턴·규칙+통계): 예) 입찰담합·법령위반 스크리닝류
- A6-3 리포트 자동생성, 근거·재현 쿼리 첨부
- A6-4 (옵션) 영상/이미지 분석·문서 분류 파이프라인

### A7. 관리자·운영 콘솔
- A7-1 워크스페이스/프로젝트/사용자·역할(RBAC), 조직 트리
- A7-2 프롬프트·에이전트·KB·도구 구성 UI(노코드 조립)
- A7-3 사용량/비용/품질 대시보드, 모델·가드 설정
- A7-4 **감사로그 뷰어**(누가·언제·무엇을·어떤 근거로), 내보내기

## B. 표준 SW 요구사항 분류별 (모든 정보화 RFP 공통 골격)

> 공공 SW 제안요청서 요구사항 상세화 표준 분류. 각 항목이 RFP에 그대로 나옴.

- **SFR 기능요구**: A1~A7의 각 기능을 요구사항 ID로 상세화(입력/처리/출력/예외). RFP별 기능은 조합·설정으로 대응.
- **PER 성능요구**: 동시 사용자 N, 응답시간(대화 스트리밍 TTFB, 검색 p95), 처리량(문서 색인 건/시), 가용성 SLA, 대용량 KB 확장.
- **ECR 시스템·장비구성**: 온프렘/프라이빗 클라우드/이중화·DR(NIA 최대 관심), GPU/CPU 산정, 컨테이너(k8s) 배포, 폐쇄망 설치 패키지.
- **SIR 인터페이스요구**: 전자정부 표준프레임워크 연계, **오픈API 제공**, SSO(행정전자서명/GPKI·간편인증), 외부 시스템/레거시 연동, 행정망↔인터넷망 연계.
- **DAR 데이터요구**: 데이터 모델·표준, 수집/정제/품질관리, 개인정보 비식별, 데이터 이관/백업/보존, 데이터셋 카탈로그.
- **TER 테스트요구**: 단위/통합/성능/보안/인수 테스트, 시나리오, **AI 품질평가(정확도·환각율·근거일치·회귀셋)**.
- **SER 보안요구**: 아래 C(보안·인증)로 상세.
- **QUR 품질요구**: 코딩표준, 정적분석, 산출물 품질, 신뢰성/유지보수성, **AI 신뢰성·안전(가드레일·편향·유해성)**.
- **COR 제약요구**: 국산모델 의무, 특정 상용SW 직접구매(BMT) 대응, 라이선스/오픈소스 정책, 표준 준수.
- **PMR 프로젝트관리요구**: WBS·일정·인력(투입공수 관리금지 대응), 품질/위험/의사소통, 주간·월간보고, 형상관리.
- **PSR 프로젝트지원요구**: 이관·교육·매뉴얼·헬프데스크·**유지관리(하자보수)**·기술지원.

## C. 필수 통과조건 — 법제도·인증 (없으면 탈락)

- C1 **전자정부법 제48조** 공공웹 표준·호환성(멀티브라우저·반응형)
- C2 **장애인차별금지법 제21조 + KWCAG 2.2 웹접근성** → **웹접근성 인증(WA/KWA-WC)** 취득 대응(마크업·명도대비·키보드·스크린리더·대체텍스트), **모바일앱 접근성 2.0**
- C3 **개인정보보호법**: 수집최소화·비식별/가명처리·접근통제·암호화·처리방침 공개·파기, 개인정보 영향평가(PIA) 대응
- C4 **CSAP**(클라우드 보안인증) — SaaS/디지털서비스몰 등록 필수, IaaS/PaaS/SaaS 등급 대응
- C5 **N2SF 국가망보안체계** — 내부망/폐쇄망 운영, 망분리·연계, 로그분석·위협탐지
- C6 보안 일반: 취약점점검·시큐어코딩(행자부 가이드)·암호화(KISA)·계정/권한·이력관리, (제품군) CC 인증·TTA GS·정보보호제품 인증
- C7 **전자정부 표준프레임워크** 채택(백엔드), 표준 컴포넌트 재사용
- C8 **정보시스템 감리** 대상 대응(요건정의·설계·종료 단계 산출물), 상호운용성/표준
- C9 **AI 신뢰성·데이터 품질**: NIA AI데이터 품질관리 가이드라인·중복제거·검증, AI 윤리/책임성(설명가능성·감사가능성)
- C10 국산 파운데이션 모델 활용(소버린 AI), 지속 모델 교체 가능성

## E. 아키텍처 개요 (기능→모듈 매핑)

```
[웹 UI: 채팅·문서·상담·관리콘솔] ── 접근성(KWCAG2.2)·SSO·RBAC
        │  (SSE 스트리밍)
[API Gateway]── 인증/권한/레이트리밋/감사로그(HITL 승인 큐)
        │
 ┌──────┼───────────────┬──────────────┬───────────────┐
[LLM 게이트웨이]   [RAG 엔진]     [에이전트/MCP]    [데이터·분석]
 벤더무관·국산     수집·색인·검색·  도구레지스트리·   질의·이상탐지·
 라우팅·비용      규정검토·인용    allowlist·HITL    리포트
        │              │               │               │
      [모델들: 온프렘 국산 / 사설 / OpenAI호환]  [벡터DB·RDB·파일·MCP서버]
        │
[영속/보안: PostgreSQL·객체스토리지·비식별·암호화·N2SF·백업/DR]
```
- 배포: 컨테이너(k8s/compose), **폐쇄망 오프라인 설치 패키지**, 이중화/DR.
- 스택 후보(사용자 자산 재사용): 백엔드 Spring Boot(Java) 또는 FastAPI, 프론트 Vue3+Vite, **osh-ai-gateway(게이트웨이)·my-computer/HARU(MCP+HITL)** 기법 흡수.

## F. 로드맵 (제안)

- **Phase 0 — MVP(범용 사용성)**: LLM 게이트웨이 + 채팅(SSE) + 문서요약/작성 + 기본 RAG + RBAC + 감사로그. 온프렘 docker-compose.
- **Phase 1 — 규정검토·상담**: 규정검토 에이전트, 민원 챗봇(다국어), HWP 입출력, 웹접근성 인증 대응.
- **Phase 2 — 에이전트·연계**: MCP 도구 + HITL 승인, 데이터 분석/이상탐지, 오픈API·SSO(GPKI).
- **Phase 3 — 공공 통과조건**: CSAP·N2SF·개인정보·표준프레임워크·감리 산출물, 국산모델 연계, DR/이중화.
- **Phase 4 — 조달 진입**: 디지털서비스몰/혁신제품 등록, PoC 레퍼런스.

> ⚠️ 냉정 주석: C(인증)·D(조달)는 **기능이 아니라 시간·비용·조직**의 문제(CSAP 취득 ~6개월, 감리·인증). 솔로/소규모는 **Phase 0~2(기술)**로 제품력을 만들고, C·D는 실 수요처(레퍼런스) 확보 후 병행이 현실적. 시장은 SI 독식이라 **틈새=온프렘·국산·경량·빠른 PoC**.
